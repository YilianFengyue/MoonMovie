# MoonMovie 设计方案（WinUI 3 桌面端）

> **v0.2 变更（2026-09-29，与用户确认）**
> - **不再使用 Python 侧车**。MoonMovie 是纯 .NET 单进程客户端，用户不需要启动任何后端。TMDB、豆瓣、资源站聚合、B 站（WBI 签名、playurl、protobuf 弹幕、扫码登录）、弹幕源全部用 C# `HttpClient` 在进程内实现。原 Python 后端和 Flutter 端只作为逻辑参考，功能重新设计。
> - 下文第 2 节中 MoonCore 负责的模块改为 `MoonMovie.Core` 里的服务。以后如需和手机联动，在 App 内按需启动 Kestrel 服务。
> - 界面：深色电影感，颜色取自海报和剧照本身，按 Fluent 规范实现，避免"AI 风"装饰。中文字体为随包附带的 **HarmonyOS Sans SC**（Regular 和 Bold）。
> - 工程结构：`src/MoonMovie`（WinUI 3，.NET 10，开发期非打包运行）+ `src/MoonMovie.Core`（net10 类库）。
>
> 版本 v0.1 · 2026-09-29
> 基于对 `CineNest/cine_net_backend`（FastAPI 后端）、`CineNest/cine_nest_app`（Flutter Android 端）、`CineLink`（Electron PC 伴侣）三个仓库的完整调研。

## 0. 结论

1. **定位**：MoonMovie 不只是 CineLink 的替代品。它要做成一个完整的桌面影视客户端（浏览、搜索、详情、播放、弹幕、历史、收藏），同时充当整套系统的**中枢**：负责托管后端、接收手机投屏、和手机同步进度。
2. **B 站可以在应用内原生播放**。原项目没做成，原因有三：
   - Companion 链路本来就只是跳转到 B 站 App 或浏览器；
   - 旧直链链路用的是 `fnval=0` 的 durl 格式，请求不带 WBI 签名和 Cookie，也没有把 `Referer` 传给播放器，所以会 403。

   这次的做法：用 `bilibili-api-python` 走 DASH（`fnval=4048`）取流，处理好 WBI 签名，支持扫码登录拿 SESSDATA，由播放器带 `Referer: https://www.bilibili.com` 直接拉 m4s，音视频分轨合流播放。B 站原生弹幕同样可以接入。
3. **技术路线**：
   - 界面和播放放在 **WinUI 3（C#，.NET 10）**；
   - 数据聚合放在 **Python 侧车 MoonCore**，由现有后端精简而来，去掉全部 AI 功能；
   - 播放内核选 **FlyleafLib**（FFmpeg + D3D11，原生 SwapChainPanel，没有空域问题），libmpv 作为备选；
   - 弹幕用 **Win2D** 自绘，由 GPU 渲染。
4. **砍掉的部分**：Agent、Chat、AI 资讯、口味 DNA、辩论推荐、MicroDesign、AutoGLM、scrcpy 镜像、LangChain 全家桶。后端依赖和启动时间都会随之大幅下降。

## 1. 现状盘点（调研结论摘要）

| 能力 | Android 端现状 | 后端现状 | 桌面端要做的 |
|---|---|---|---|
| 首页 | 直连 TMDB，13 个分类，固定列数网格 | `/api/feed` 强耦合 LLM | Xbox 式 Hero + 内容行 + 瀑布流 |
| 搜索 | 只搜 TMDB，没有联想，没有防抖 | MacCMS 只做精确归并，按来源数排序；没有模糊匹配、拼音、联想 | 统一搜索、联想、模糊匹配、多域结果 |
| 找片源 | 本地聚合 20 个 MacCMS 源，流式返回、有健康度；**只保留集数最多的一条线路** | 另有两套引擎（video_engine、resources）并存 | 保留全部线路，测速择优，出错自动切换 |
| 播放 | media_kit(mpv)，只支持 HLS 和 MP4；**续播没接通**；播放页不能换源 | `/api/play/resolve` 只取第 1 集，headers 为空 | 原生硬解、续播、换源、预加载、去广告 |
| B 站 | 跳转 App 或浏览器；旧链路 WebView | 匿名搜索与排行；直链不可用 | **应用内 DASH 播放、扫码登录、原生弹幕** |
| 弹幕 | 弹弹play 或 LogVar，用 canvas_danmaku 渲染 | 没有 | 弹弹play、LogVar、B 站三源，Win2D 渲染 |
| 历史/收藏 | Hive 本地存储，key 为 `source:id` | 表按 TMDB id 建，单用户，关闭了 journal | 统一的媒体身份模型，存 SQLite WAL，供多端同步 |
| 用户 | 没有 | 没有鉴权，CORS 为 `*`，开放图片代理有 SSRF 风险 | 本地多档案、B 站账号、手机配对令牌 |
| 投屏 | 手机发送 `load_remote` | `/ws/pc-control/{room}` 只做广播 | MoonMovie 替代 CineLink 成为接收端 |

**需要注意的遗留问题**：
- 两套 TMDB 客户端的鉴权行为不一致。
- `GET /api/movie/{id}` 有写历史的副作用。
- Flutter 请求的 `/api/poster/{id}` 在后端不存在。
- Flutter 端的 TMDB Key 是硬编码的。
- `.env` 里有重复键，`DEEPSEEK_*` 是死配置。

### 2.1 为什么数据侧用 Python 侧车，而不是全部改写成 C#

- **B 站**：`bilibili-api-python` 已经处理了 WBI 签名、`curl_cffi` 指纹、protobuf 弹幕、扫码登录和风控细节。这部分用 C# 重写成本最高，风控上也最容易出问题。
- **复用**：MacCMS 聚合、豆瓣、TMDB、影视库刮削都已经写好并有测试。
- **配套**：手机端已经在调用这些接口（`/api/health`、`/api/bili/movie/videos`、`/api/library*`、`/ws/pc-control`）。PC 托管后端后，手机不用改代码就能继续工作。
- **延迟敏感的部分全部放在 C# 进程内**：图片加载、媒体代理、播放、弹幕渲染。MoonCore 只负责"查数据"，localhost 往返约 1ms，可以忽略。

### 2.2 侧车生命周期（SidecarManager）

- App 启动时和 UI 并行拉起 MoonCore，选一个随机空闲端口，生成随机令牌并通过环境变量传入。
- 把子进程放进 **Job Object**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），主程序无论怎么退出，子进程都会一起结束（CineLink 靠 `taskkill /t` 兜底，不可靠）。
- 就绪判定：轮询 `/api/health`。就绪之前 UI 先用本地缓存渲染首页（stale-while-revalidate），避免冷启动白屏。
- 崩溃时自动重启，指数退避；日志用环形缓冲，可以在设置页查看。这部分借鉴 CineLink 的"后端管家"。
- 分发：
  - 开发期用 `backend/.venv`；
  - 发布期用 python-build-standalone 加预装依赖（onedir），放在 `LocalAppData`；或者 PyInstaller onedir。**不用 onefile**，因为每次启动都要解包，太慢。
- 去掉 LangChain、LangGraph、openai、playwright 之后，import 时间预计从数秒降到 1 秒以内。

## 4. 界面设计：Fluent + Xbox 沉浸感

### 4.1 设计语言

- **窗口**：`ExtendsContentIntoTitleBar` 加 `TitleBar` 控件；壳层用 MicaAlt 背景；Flyout 和面板用 Acrylic。
- **核心沉浸手法**（复刻 Xbox Dashboard）：
  1. **动态背景**：焦点移到哪张卡片，全屏背景就换成它的 backdrop。做法是两层 Image 交叉淡入 400ms，再叠一层底部和左侧的渐变遮罩，外加轻微的 Ken Burns 缓慢缩放。
  2. **主题色取样**：从海报提取主色，写入页面级的 accent 画刷。按钮、进度条、渐变都随内容变色；取色结果缓存起来。
  3. **焦点放大**：卡片获得焦点或悬停时放大到 1.08 倍，并加上阴影和描边光晕。用 Composition 的 `ImplicitAnimations` 实现，不走布局，保持 60/120fps。
  4. **Logo 标题**：详情页和 Hero 优先显示 TMDB `images/logos`（zh 优先，其次 en）的透明标题图，没有时才回退到文字。
  5. **连接动画**：海报从网格"飞"进详情页，用 `ConnectedAnimationService`。
- **导航**：顶部水平导航（首页 / 电影 / 剧集 / 动漫 / B站 / 媒体库），右侧是搜索框（`Ctrl+K`）、历史、档案头像。进入播放器时导航完全隐藏。
- **10-foot 模式**：支持手柄。启用 XY 焦点导航和 `Windows.Gaming.Input`：A 确认、B 返回、LB/RB 切换导航、Y 搜索。全屏加手柄就是"主机模式"。
- **动效节奏**：统一使用 Fluent 缓动曲线（`0.1,0.9,0.2,1`）；时长分 167、250、400ms 三档；开启系统"减少动画"时自动降级。

## 5. 播放系统（性能与延迟是重点）

### 5.1 播放内核：FlyleafLib

- 基于 FFmpeg 解码和 D3D11 渲染，自带 WinUI 3 控件 `FlyleafHost` 和 `FullScreenContainer`，**画面在 XAML 树内部**。弹幕层和控制层可以直接叠在上面，没有 mpv `wid` 子窗口那种空域问题。
- 支持 D3D11VA 硬解、HDR 转 SDR、NVIDIA/Intel 超分；格式覆盖 HLS、MP4、FLV、MKV、HEVC 等。
- 抽象出 `IPlayerEngine`（Open、Play、Seek、Rate、Tracks、事件），Flyleaf 作为默认实现。**第一周先做技术验证**，确认以下几点：
  1. 在当前 WindowsAppSDK 版本下能正常宿主；
  2. 能通过 FFmpeg format options 给请求加 headers（Referer、UA）；
  3. B 站 DASH 分离的音频流能以外部音频流的方式挂载。

  如果第 3 点不满足，有两条退路：由 MediaProxy 生成本地 MPD；或者切到 libmpv 引擎（`audio-files` 加 `http-header-fields`）。

### 5.2 起播延迟优化

| 手段 | 说明 |
|---|---|
| **预解析** | 进入详情页就在后台搜源和解析线路；鼠标悬停在「播放」上时预取 m3u8 和首个分片。 |
| **竞速择源** | 对排名前 3 的候选并发预检（m3u8 可解析，首个 ts 的 TTFB 最短），谁先通过就用谁，其余留作热备。这个做法类似 Happy Eyeballs。 |
| **FFmpeg 参数** | 调低 `probesize` 和 `analyzeduration`，开启 `reconnect*`、`http_persistent`、`multiple_requests`，`SeekAccurate=false`，`MinBufferDuration` 约 0.5s 即可起播。 |
| **续播** | 从进度记录中读取 `positionMs`，打开时直接 seek（修复 Android 端没接通的问题）。 |
| **下一集预加载** | 播放到 90% 时预解析下一集，并预热前 2 个分片。 |
| **自动容错** | 卡顿看门狗：缓冲超过 8 秒且进度不前进时，自动切到热备源并保持当前进度。播放页可以随时手动换源和换线路。 |

### 5.3 MediaProxy（C# 进程内，Kestrel 绑定 127.0.0.1）

- **m3u8 去广告**：MacCMS 源常在 `#EXT-X-DISCONTINUITY` 区间里插入广告片段，按 MoonTV/LunaTV 的做法识别后剔除。
- **header 注入**：给分片请求统一加上 Referer 和 UA，解决防盗链。
- **分片预取和内存缓存**：seek 回退时直接命中缓存。
- **可观测**：记录每个分片的耗时和码率，结果回写源的健康度。

### 5.4 播放器界面与交互

- 控制层 3 秒无操作后自动隐藏，鼠标移动时唤出。
- 底栏：进度条（悬停时显示时间，有章节时显示章节）、播放/暂停、下一集、音量、倍速（0.5–3x）、画质（B 站）、线路/片源、选集抽屉、弹幕开关与设置、字幕和音轨、画中画（`AppWindowPresenterKind.CompactOverlay`）、全屏。
- 快捷键：
  - Space：播放/暂停；
  - ←/→：±5 秒，Shift 加方向键 ±30 秒；
  - ↑/↓：音量；
  - F：全屏；
  - D：弹幕；
  - N：下一集；
  - `[` 和 `]`：调倍速；
  - 长按 → 键：临时 3 倍速。
- 跳过片头片尾：按剧集记住用户设定的时间点，之后每集自动应用。

## 6. 智能搜索（不依赖 AI，但要强）

### 6.1 查询理解（MoonCore `search/`）

- **归一化**：全半角转换、繁简转换（zhconv 或 OpenCC）、去除标点和空白、中文数字与阿拉伯数字互转、罗马数字转换（Ⅱ→2）。
- **结构解析**：年份（`2014`、`(2014)`）；季集（`第二季`、`S02`、`S2E5`、`第5集`）；类型提示词（"电影""剧"）。
- **别名扩展**：用 TMDB `alternative_titles` 和 `translations` 建立中英、港台译名映射，并缓存到 SQLite。这样可以替换掉旧引擎里硬编码的别名表。
- **拼音**：历史和收藏支持全拼和首字母匹配（pypinyin），例如 `xjcy` 能搜到"星际穿越"。

### 6.2 联想建议（输入即搜）

- 防抖 200ms。三路并发：本地历史和收藏（拼音）、TMDB multi search 前 8 条、上次热词。结果按请求版本号去乱序。
- 下拉面板里带小海报、年份和类型；支持方向键选择，回车后直接进入详情页。

### 6.3 结果页（分域流式呈现）

1. **最佳匹配**：大卡片，展示 backdrop、Logo 和「播放」按钮。
2. **影视**：TMDB 和豆瓣合并（沿用 catalog 的合并规则），可按类型、年份、排序筛选。
3. **人物**：演员或导演，点击进入作品页。
4. **可播放片源**：MacCMS 结果通过 WebSocket 或 SSE **流式**推送，界面显示"已完成 12/20 源"。
5. **B 站**：视频、番剧、UP 主。
6. **本地媒体库**。

**排序公式**：`score = 文本相似度(rapidfuzz WRatio，基于归一化标题和别名) × 权重 + 年份吻合 + 热度(log) + 可播性 + 源健康度`。低质量词（解说、预告、花絮）在"可播放片源"域里降权，但在 B 站域里不降。

### 6.4 从 TMDB 条目反查片源（修复现有问题）

- 用中文名、原名和别名并发搜索 MacCMS。
- 匹配依据：归一化标题加年份，剧集再核对集数与 TMDB `number_of_episodes` 是否接近。
- **保留全部线路**：Android 端只保留集数最多的那一组，这里不再丢弃，用户可以自己选线路。

## 7. 弹幕系统

### 7.1 数据源（MoonCore `danmaku/` 统一输出）

| 源 | 用途 | 说明 |
|---|---|---|
| B 站原生 | 播放 B 站视频时使用 | `get_danmakus` 读 protobuf 分段，按 6 分钟一段懒加载 |
| 弹弹play | 影视和动漫 | 需要 AppId 和 AppSecret（原项目存在手机 Hive 里，**不在 .env 中**，需要你提供）；按 TMDB id、标题和集号匹配 |
| LogVar | 兼容弹弹play 接口的聚合服务 | 需要 baseUrl 和 token（同样需要你提供） |

统一格式为 `{t_ms, mode(scroll|top|bottom), color, text, source}`。匹配结果按剧集缓存。手动匹配面板可以纠正错配。

### 7.2 渲染引擎（C#，Win2D）

- 一个 `CanvasAnimatedControl` 或 `CanvasSwapChainPanel` 叠在视频上方，**时钟取播放器时间**，暂停、seek 和倍速都自动同步。
- 用 `CanvasTextLayout` 缓存文字排版并复用对象，渲染时零分配。
- 轨道分配算法：滚动弹幕按"尾部可追及"原则判断碰撞，顶部和底部弹幕按停留时长分配槽位。
- 游标加二分查找派发弹幕（沿用 Android 端的思路）。
- 过滤：密度采样（按哈希确定采样，seek 后不闪烁）、合并重复、关键词和正则屏蔽、隐藏彩色和高级弹幕。
- 设置项：不透明度、字号、显示区域（1/4、1/2、3/4、全屏）、速度、描边或阴影。
- 性能目标：5000 条同屏密度下保持 120Hz 不掉帧，CPU 占用低于 5%。

## 8. B 站模块（MoonCore `bili/` 扩展）

| 功能 | 实现 |
|---|---|
| 扫码登录 | 用 `bilibili-api-python` 的二维码登录，UI 展示二维码并轮询状态。拿到 Credential 后用 DPAPI 加密存到本地，可以随时退出登录 |
| 取流 | `Video.get_download_url` 加 `fnval=4048`，拿到 DASH 视频和音频的多个清晰度及编码（AVC/HEVC/AV1）。不登录一般只有 480P，登录后 1080P，大会员 4K/HDR。按硬解能力选择编码 |
| 播放 | 视频和音频两路 m4s，带 Referer 和 UA；备用 CDN（`backup_url`）自动切换；URL 过期（约 120 分钟）后自动重新获取 |
| 弹幕 | protobuf 分段弹幕，另可选高级弹幕 |
| 心跳 | 登录后可选上报播放进度，同步到 B 站历史 |
| 内容 | 沿用现有的 search、video、rank、hot、weekly、up 接口；新增番剧 PGC（`ep_id`/`season_id`）播放，有地区和会员限制时给出清楚的提示 |
| 风控 | 全局限流（沿用 Semaphore(3)），加进程内 TTL 缓存；请求集中在 MoonCore 一处发出 |

## 9. 数据与用户

### 9.1 统一媒体身份

```
MediaKey = "tmdb:movie:157336" | "tmdb:tv:1396" | "bili:BV1xx" | "bili:ep:12345" | "local:<hash>" | "maccms:<src>:<id>"
```

- 历史、收藏和进度都挂在 MediaKey 上；剧集另加 `season/episode`。
- MacCMS 片源只是 TMDB 条目的"播放来源"，不作为身份。这样换源不会导致历史断裂，这是 Android 端现在的问题。

### 9.2 表结构（MoonCore SQLite，WAL 模式，用 aiosqlite 异步访问）

- `profiles(id, name, avatar, color, created_at)`
- `watch_progress(profile_id, media_key, season, episode, position_ms, duration_ms, source_hint, updated_at, PK(profile_id, media_key, season, episode))`
- `watch_history(profile_id, media_key, title, poster, last_episode_label, updated_at)`
- `favorites(profile_id, media_key, status: want|watching|done, list_id, added_at)`，外加 `lists(id, profile_id, name)`
- `media_cache(media_key, payload_json, fetched_at)`：TMDB 详情缓存
- `source_health(source_id, avg_ms, success, fail, last_error, updated_at)`
- `bili_account(profile_id, credential_enc, uname, face, vip, updated_at)`
- `search_history(profile_id, query, at)`、`alias(media_key, alias)`

### 9.3 用户体系

- **本地多档案**：模仿 Xbox 和 Netflix 的"谁在看"选择页。每个档案有独立的历史、收藏、B 站账号和偏好。不做云账号。
- **手机配对**：PC 显示二维码，载荷兼容原协议 `{v, app:"cinenest", name, candidates[]}`，并新增 `token`。手机扫码后持有令牌访问 MoonCore。此后历史和进度双向同步：在手机上看到一半，回到 PC 可以接着看。
- **安全**：
  - 默认只监听 127.0.0.1；
  - 开启"手机联动"后才监听局域网，并强制校验令牌；
  - 图片代理改成域名白名单（TMDB、豆瓣、B 站的图片域名），并恢复 TLS 校验，修复原有的 SSRF 问题。

## 10. 与手机端的配套

- **投屏接收**：MoonMovie 实现 `/ws/pc-control/{room}` 协议 v2，协议照搬 CineLink：
  - 消息：`load_remote` 加 headers 和弹幕，`play`、`pause`、`seek`、`setRate`、`danmakuToggle`、`stop`；
  - 用 `sender:"pc"` 过滤自己发出的回环，用 `loadSeq` 支持重新投送；
  - 播放状态每秒节流回报一次。

  手机"投屏到 PC"的功能不需要任何改动。
- **兼容接口**：`/api/health`、`/api/bili/movie/videos`、`/api/library*`、`/api/local-videos/stream/*`、`/api/catalog/search` 保持原样，Android 端可以继续使用。
- **后续**：可以把手机端的 Hive 历史迁移到 `/api/sync/*` 接口，实现真正的双端同步。

## 11. 配置与密钥

- `backend/.env` 直接复制原项目的 `cine_net_backend/.env`。保留 TMDB 和资源站相关变量，删除 `LLM_*`、`DEEPSEEK_*`、`PHONE_*`（AI 和 AutoGLM 相关），并清理重复键。
- 新增的配置项：
  - `TMDB_MODE`（direct/proxy/custom），默认使用原 App 的 Cloudflare 反代，解决国内直连 TMDB 的问题；
  - `DANDAN_APP_ID`、`DANDAN_APP_SECRET`、`LOGVAR_BASE_URL`、`LOGVAR_TOKEN`；
  - `MOONCORE_TOKEN`，由主程序在启动时注入。
- 仓库初始化 git 时，把 `.env`、`*.db`、`backend/.venv` 加进 `.gitignore`。
- Flutter 端硬编码的 TMDB Key 可以作为 `.env` 中 `TMDB_API_KEY` 的备用值。

## 13. 风险

| 风险 | 应对 |
|---|---|
| Flyleaf 与 WindowsAppSDK 新版本的兼容性，或者不支持分轨 DASH | 做了 IPlayerEngine 抽象，M0.5 先验证，libmpv 作为退路 |
| 免费 MacCMS 源不稳定、有插播广告 | 健康度统计、竞速择源、热备切换、去广告代理；支持导入 MoonTV 源配置以便更新 |
| B 站风控或接口变更 | 请求集中在一处，限流加缓存；依赖库保持更新 |
| TMDB 在国内无法直连 | 默认走反代，可以自定义代理，详情缓存到本地 |
| 版权 | 聚合源属于第三方资源，项目只做个人学习用途，不公开分发片源配置 |
